## 3. Dead ends (do NOT retest)

1. **Float `stem_trunk_credit`** (any value 0.2/0.3/0.5/0.7). GA cannot
   optimise a weighted-magnitude trunk signal; it needs a strong binary
   "any trunk cell = good". Only `stem_trunk_presence: true/false` works.
   *Source: memory `project_credit_experiments_2026-04-17.md`, experiments
   #11–13 above.*
2. **`t_trunk_weight` at current action space.** 6-config sweep earlier
   proved `t15 ≡ t30` bit-identically. Even with directional divide
   actions landed, no recorded experiment has isolated a measurable
   effect of this weight. Exclude from HPO search spaces.
3. **Locking `world_seed` per generation** (looks like a bug, is a free
   regulariser — regressed 0.41 → 0.26 when "fixed" earlier). Leave varying.
4. **Adaptive mutation alone without positional encoding.** All 4
   `ablation_adaptive_*` runs scored MS-10 = 0.134. Only meaningful in
   combination with `use_position: true`.
5. **Longer training ≠ better.** Champion 120-gen run peaked gen 75 at
   0.389, ended 0.342, MS-10 0.325. Plateau_patience ≥ 40 is sufficient.
6. **Declaring a champion from training peak IoU** without multi-seed
   benchmark. `sweep_a2_*` had training peak 0.375 but MS-10 0.251.
7. **Raising late-phase `die_cap_schedule` cap above 0.35** (tested
   0.60 → MS-10 0.30, −31% from baseline 0.440; alive cells went UP
   not down). Hard simulation-side caps don't provide a fitness
   gradient — GA compensates by spawning more stems. For stem-clutter
   attacks, use fitness-side levers instead (`stem_cleanup_multiplier`,
   `stem_corridor_end_scale`). Exp #17, 2026-04-21.
8. **Stem-specific fitness penalties alone** (tested
   `stem_cleanup_multiplier: 1.5 → 2.5` in exp #18 → MS-10 0.38, −14%).
   Cleanup worked (alive 95 → 57), but GA escaped by differentiating
   stems into type-A cells instead of killing them: `alpha_fp (2.88) <
   stem_cost (3.20)` makes `a` cells cheaper than `S` cells. Result:
   phantom row-3 bar of 12 `a` cells = new FP source. Do NOT raise
   stem-specific penalties in isolation — they trigger the
   differentiation escape-hatch. Either couple with higher generic FP
   pressure (alpha_fp, late_t.fp_multiplier) OR use a different axis
   entirely. Exp #18, 2026-04-21.
9. **Combined stem_cleanup_multiplier=2.5 + late_t.fp_multiplier=1.8**
   (tested #20 → MS-10 0.3786 BIT-IDENTICAL to #18). Code verified
   correct — parameter IS applied. But stem=2.5 dominates fitness
   landscape so completely that fp_multi change 1.2→1.8 doesn't shift
   GA selection ranking — same elites, same children, same final
   model. Combining two fitness levers fails when one dominates the
   other. To escape a dominant-parameter basin: either revert the
   dominant parameter OR raise secondary by orders of magnitude.
   Exp #20, 2026-04-23.

## 6. Root cause of the April 12–19 loop

Per the 2026-04-19 audit (B-table row #4, anti-pattern #3): five configs
`exp_curriculum_v6–v10` tested `stem_trunk_credit` float values **after**
`68152e0` had already exposed the bug that made earlier variants look
good. There was no prior-check step, no written hypothesis with a
success criterion, and no single document to compare against. This
Decision Doc is that document going forward.

Rule (per w1-t3, experiment-loop skill, w4-t1): every experiment from
this date onward appends one row to the §2 table and either closes an
entry in §4 or adds a new row in §3.
